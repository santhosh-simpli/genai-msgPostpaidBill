# Database Demo Guide - MSG Telecom Postpaid Billing System

A quick reference for demonstrating the database layer, schema, and queries for the application.

---

## 🗄️ Database Technology
- **Type:** H2 In-Memory Database (for development/demo)
- **JDBC URL:** `jdbc:h2:mem:postpaid_billing`
- **Username:** `sa`
- **Password:** (empty)
- **Driver:** `org.h2.Driver`
- **Console:** http://localhost:8080/h2-console
- **Schema:** Auto-generated by JPA/Hibernate on startup

---

## 🏗️ Schema Overview

### Main Tables
- **users**: Stores user accounts (admin, operator, customer)
- **customers**: Customer profiles linked to users
- **services**: Service subscriptions (Mobile, Broadband, etc.)
- **usage_records**: Tracks service usage (voice, data, etc.)
- **invoices**: Billing records for customers
- **payments**: Payment transactions for invoices

### Relationships
- **User 1:1 Customer** (each customer has a user account)
- **Customer 1:N Services** (one customer, many services)
- **Service 1:N UsageRecords** (one service, many usage records)
- **Customer 1:N Invoices** (one customer, many invoices)
- **Invoice 1:N Payments** (one invoice, many payments)

## 🗂️ Table Structure Snippets

### users
```sql
CREATE TABLE users (
  user_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(255) NOT NULL UNIQUE,
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role VARCHAR(20) NOT NULL,
  first_name VARCHAR(255),
  last_name VARCHAR(255),
  created_at TIMESTAMP
);
```

### customers
```sql
CREATE TABLE customers (
  customer_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  first_name VARCHAR(255),
  last_name VARCHAR(255),
  email VARCHAR(255),
  phone_number VARCHAR(50),
  address VARCHAR(255),
  user_id BIGINT,
  FOREIGN KEY (user_id) REFERENCES users(user_id)
);
```

### services
```sql
CREATE TABLE services (
  service_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  service_type VARCHAR(50),
  plan_name VARCHAR(100),
  customer_id BIGINT,
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

### usage_records
```sql
CREATE TABLE usage_records (
  usage_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  usage_date DATE,
  usage_amount DOUBLE,
  unit VARCHAR(20),
  service_id BIGINT,
  FOREIGN KEY (service_id) REFERENCES services(service_id)
);
```

### invoices
```sql
CREATE TABLE invoices (
  invoice_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  billing_start_date DATE,
  billing_end_date DATE,
  total_amount DOUBLE,
  status VARCHAR(20),
  customer_id BIGINT,
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

### payments
```sql
CREATE TABLE payments (
  payment_id BIGINT AUTO_INCREMENT PRIMARY KEY,
  amount DOUBLE,
  payment_date DATE,
  payment_method VARCHAR(50),
  invoice_id BIGINT,
  FOREIGN KEY (invoice_id) REFERENCES invoices(invoice_id)
);
```

## 📊 Sample Queries

### 1. List All Users
```sql
SELECT user_id, username, email, role, first_name, last_name FROM users ORDER BY user_id;
```

### 2. List All Customers with User Info
```sql
SELECT c.customer_id, c.first_name, c.last_name, c.email, c.phone_number, u.username, u.role
FROM customers c
LEFT JOIN users u ON c.user_id = u.user_id
ORDER BY c.customer_id;
```

### 3. Recent Invoices
```sql
SELECT i.invoice_id, i.total_amount, i.status, i.billing_start_date, i.billing_end_date,
       c.first_name || ' ' || c.last_name AS customer_name
FROM invoices i
JOIN customers c ON i.customer_id = c.customer_id
ORDER BY i.invoice_id DESC
LIMIT 10;
```

### 4. Payments with Invoice Details
```sql
SELECT p.payment_id, p.amount, p.payment_date, p.payment_method,
       i.invoice_id, i.total_amount AS invoice_amount, i.status AS invoice_status,
       c.first_name || ' ' || c.last_name AS customer_name
FROM payments p
JOIN invoices i ON p.invoice_id = i.invoice_id
JOIN customers c ON i.customer_id = c.customer_id
ORDER BY p.payment_date DESC
LIMIT 20;
```

### 5. Usage Records by Service Type
```sql
SELECT u.usage_id, u.usage_date, u.usage_amount, u.unit,
       s.service_type, s.plan_name,
       c.first_name || ' ' || c.last_name AS customer_name
FROM usage_records u
JOIN services s ON u.service_id = s.service_id
JOIN customers c ON s.customer_id = c.customer_id
WHERE s.service_type = 'Mobile'
ORDER BY u.usage_date DESC
LIMIT 50;
```

### 6. Pending Invoices
```sql
SELECT i.invoice_id, c.first_name || ' ' || c.last_name AS customer_name,
       i.total_amount, i.billing_start_date, i.billing_end_date
FROM invoices i
JOIN customers c ON i.customer_id = c.customer_id
WHERE i.status = 'PENDING'
ORDER BY i.billing_end_date DESC;
```

### 7. Statistics
```sql
SELECT 
    COUNT(CASE WHEN status = 'PENDING' THEN 1 END) AS pending_invoices,
    COUNT(CASE WHEN status = 'PAID' THEN 1 END) AS paid_invoices,
    COUNT(CASE WHEN status = 'OVERDUE' THEN 1 END) AS overdue_invoices,
    SUM(CASE WHEN status = 'PENDING' THEN total_amount ELSE 0 END) AS outstanding_amount,
    SUM(CASE WHEN status = 'PAID' THEN total_amount ELSE 0 END) AS total_paid
FROM invoices;
```

## 💡 Pro Tips
- H2 is in-memory: data resets on restart
- Schema is auto-generated from JPA entities
- Use LIMIT in queries for large tables
- Use JOINs to show relationships
- For production, switch to PostgreSQL/MySQL and use Flyway/Liquibase for migrations
